## Key Modules

### content/main.js — Entry Point & Coordination
- Creates `ParserRegistry`, identifies matching parser, initializes `BooruEaglePanel`.
- **Sankaku Quick Parse**: `ensureParsedData` tries immediate parse first; tags load asynchronously via `waitForTagsInBackground` (waits for `#tag-sidebar` + `#image[orig_width][orig_height]`).
- **Rule34 blocked page detection**: checks for 429/CAPTCHA on post page load, provides auto-refresh and banner polling.
- **Naming format resolution**: resolves file naming based on `window.extensionSettings.fileNameFormat` (`postId` vs `original filename`).
- **Note/Annotation integration**: passes notes/About description into save queue when `parseNotes` setting is enabled.
- **SPA Navigation Management**: observes `popstate`, `hashchange`, Modern Navigation API, and history methods to gracefully tear down and reinitialize panels without leaking listeners.
- **Hidden tab parse handler (`handleParseForMainPageSave`)**: executes in background tabs opened for thumbnail saves.
- **Sample warning**: when the parsed image URL is a reduced sample/preview (`BaseParser.isSampleImageUrl`), the save proceeds but the user is warned (toast on post pages; `sampleOnly` flag returned to the source tab for thumbnail saves).

### content/panel.js — Floating Panel
- Cross-domain synchronization via `chrome.storage.local` with unique `_panelId` to prevent echo loops.
- Features: draggable glassmorphism UI, collapse/expand, Set Parent (Alt+X), Post-Save auto-close toggle (Alt+A), Stop (Alt+C), toast alerts, rating highlight.
- Visual collected indicators (green checkmark for collected items; recollecting indicator).
- `updatePostIdDisplay()`: shows `#site-name` on main pages and highlights in green when parent post is locked.

### content/main-page-buttons.js — Thumbnail Buttons
- Reads `SITE_CONFIGS` for site-specific post card and container selectors, `THUMB_BUTTON_CONFIG` for styling.
- Extracts `directPostUrl` from thumbnail anchor tags to ensure hidden tabs open the exact post URL (crucial for KVS slug routing).
- Uses `MutationObserver` for infinite scroll feeds.
- Long-press (~500ms) sets thumbnail as parent post.
- Memory management: `processedPosts` and `buttonMap` automatically pruned above 1000 items.
- **Collected badges**: `checkCollectedBatch()` sends `{postId, postKey, pHash, thumbUrl}` to the background and renders `collected` (exact post match), `NN%` (pHash match) or `upgrade` (web resolution higher than the Eagle copy).
  - Thumbnail fingerprints (pHash + block levels) are computed locally when the image is readable, otherwise by the background; the background result is kept in `postInfoMap` so rechecks never re-download thumbnails.
  - Sites with `hashThumbsInPage` (Danbooru) fetch thumbnails from the page context, because their CDN rejects service-worker requests (Cloudflare).
  - Badge listeners read the latest match from `badge._details` (a recheck can point a badge at another Eagle item).
  - Resolution comes from thumbnail markup; sites without it (Rule34, Gelbooru) fetch the post page only after a 300 ms hover (no proactive requests because of Cloudflare/rate limits), so `upgrade` may appear only after hovering.
- `extractTagsFromPost()`: thumbnail tag list (`data-tags`, or the `title`/`alt` formats of yande.re/Konachan and Gelbooru/Rule34) for the tag-count comparison.

### content/comparison-card.js — Duplicate Inspector
Popover shown when hovering a collected/similarity badge:
- **Eagle / Web** resolution and size; `Replace in Eagle` when the web copy is larger.
- **Image verdict**: `Same post` (exact match) / `Looks identical` / `Alt version (visible changes)`.
- **Tags**: tag counts of the Eagle copy (live `/api/item/info`, without `rating:`/`parent:`) vs the web post; the larger one is highlighted.
- **Eagle parent**: value of the Eagle copy's `parent:` tag.
- **Diff map**: the web thumbnail with red 16×16 blocks where it differs from the Eagle copy.
  - Primary source: block brightness levels. Both sides are z-score normalized; a block counts as changed above `BLOCK_DIFF_THRESHOLD` (0.35 σ). The same image across sites measures 0.02–0.09, alt versions 1.4+.
  - Fallback for database items without block levels: differing pHash bits plus `SAME_IMAGE_MAX_DISTANCE` (8 bits). pHash bits only say "above/below band median", so they flip on noise and miss changes that don't cross the median — hence the brightness-based map.
  - Limitation: very small edits (eyes, tiny details) fall below the 16×16 grid resolution.
- Replace on something that looks like an alt version shows a warning and a `Replace anyway` button.

### content/blockhash.js — Fingerprints
- `computeSourceFingerprint()` / `computeElementFingerprint()` / `computeBlobFingerprint()` return `{ pHash, blocks }`: 256-bit bmvbhash (64 hex) + 256 block brightness levels (base64, 0–255).
- `resampleBilinearAA()` reproduces Pillow's `Image.resize(BILINEAR)` exactly (antialiased triangle filter, 22-bit fixed-point weights, horizontal then vertical pass), so the browser and `pHash_collector.py` produce bit-identical results. Browser canvas downscaling is not used for hashing: it skips pixels and makes the hash noisy (~89% self-similarity instead of ~98%).
- Block level = `floor((r+g+b of 2×2 px + 6) / 12)` — identical integer rounding in JS and Python.

### content/parsers/ — Plugin System
- `BaseParser` defines interface: `matches()`, `isPostPage()`, `getImageUrl()`, `getRawTags()`, `getPostId()`, `getImageDimensions()`, `getSourceUrl()`, `getRating()`, `getNotes()`, `getAnnotation()`.
- `parse()` is unified and returns normalized data: `{ site, siteType, imageUrl, tags, dimensions, postId, sourceUrl, rating, annotation, pageUrl }`.
- `Rule34VideoParser`:
  - Extracts highest quality MP4 URL (evaluates 1080p -> 720p -> 480p -> 360p from `.tag_item_download` and `flashvars`).
  - Scopes tag extraction strictly to `#tab_video_info .row.vp-tags .tag_vote_chip` (characters, tags, categories, and `artist:` models).
  - Implements `getAnnotation()` to extract the video "About" description with formatted line breaks.
- `Rule34Parser`: includes static blocker checks and DOM note parser.
- `SankakuParser`: static `waitForElement(selector, timeout)` for dynamic DOM nodes.
- `BaseParser.isSampleImageUrl(url)`: detects reduced copies (`/sample/`, `/samples/`, `/preview/` folders, `sample_`/`sample-` file names). Parsers keep their URL selection; callers only warn.

### background/service-worker.js — Core Engine

#### 1. DownloadSaveQueue
- **Task states**: `pending_parse` → `pending_download` → `downloading` → `download_complete` → saved / failed.
- **Two-Phase Enqueue**: thumbnail saves immediately enqueue as `pending_parse` (capturing FIFO click order) while hidden tabs parse asynchronously.
- **Tag merging**: preserves `parent:xxx` tags when updating task with parsed tags.
- Keep-alive alarms (`booru-eagle-keepalive`) prevent service worker idle termination during downloads.
- Full memory cleanup: chunks and base64 strings nulled immediately after dispatch.

#### 2. Resilient Multi-Strategy Download Pipeline
- **Browser Streaming (Base64)**:
  - Streams chunks via `response.body.getReader()` to report real-time progress (`Downloading X.X/Y.Y MB`).
  - Adapts credential modes per site: `omit` on first attempt for redirecting video CDNs (e.g., `rule34video.com`), `include` for standard boorus, with retry support.
  - Large file protection: files >60MB automatically bypass base64 encoding and delegate directly to Eagle.
- **Auto-Fallback to Eagle Direct URL (`saveToEagleURL`)**:
  - If browser `fetch` fails (due to cross-domain CORS, CDN redirect targets, network interruption, or memory constraints), the task automatically switches to `useUrlDirect = true`.
  - Dispatches `POST /api/item/addFromURL` directly to Eagle desktop app, passing `headers: { referer, cookie, user-agent }`.
  - As a native desktop application, Eagle has no browser CORS restrictions and downloads video streams directly to disk.

#### 3. Hidden Tab Save Flow
1. `handleHiddenTabParse()` enqueues task in `pending_parse` state immediately → returns position to UI.
2. `_parseHiddenTabInBackground()` opens hidden tab using exact `directPostUrl` or fallback `/video/${id}/video/`.
3. `waitForCorrectUrl()` verifies the expected post ID has loaded, preventing race conditions from reused browser tabs.
4. Content script parses metadata and annotation.
5. `queue.updateParsedData()` transitions task to ready state for download and saving.
6. Hidden tab is closed automatically once the download phase finishes.

#### 4. Collected Database & pHash Deduplication
- Bundled database (`downloaded-db.json`) + `chrome.storage.local` lists of items saved since (`customPostList`, `customPHashList`).
- Matching (`checkCollectedBatch`): exact `postKey` match first, then the nearest pHash by Hamming distance over a contiguous `Uint32Array` (`PHASH_SIMILARITY_THRESHOLD` = 0.88, i.e. ≤ 30 of 256 bits).
- **Thumbnail fingerprint cache**: `getThumbFingerprintBg()` keeps an LRU of 5000 `thumbUrl → {pHash, blocks}`; concurrent requests share one fetch; failures are retried after 2 minutes. Computed fingerprints are returned to the page (`queryPHash`, `queryBlocks`).
- **Background-fetchable URLs**: `toBackgroundFetchableUrl()` maps hosts that challenge non-page requests to an open mirror (Rule34 `wimg.rule34.xxx` → `api-cdn.rule34.xxx`). Danbooru thumbnails are hashed in the page instead, with a DNR session rule granting CORS on `cdn.donmai.us` to `danbooru.donmai.us` fetches only.
- New saves store `{id, pHash, blocks, w, h, size, ext, postKey}` (extension from the image URL; the downloaded Blob is untyped).
- **Eagle sync** (`syncFromEagleApiBg(true)`, on startup and tab activation at most every 15 s): purges items deleted in Eagle from memory and storage, resolves temporary `saved_*` IDs by `postKey`.
  - Safety guard (`checkAuthoritativeSyncSafety`): the purge runs only against the library the data belongs to. The home library path is remembered in `eagle-home-library`; an unknown or different path is accepted only if ≥ 50% of known Eagle IDs are present (same library moved/renamed). Another open library or an empty list (Eagle still loading) skips the sync.
  - Tabs are notified (`collectedCacheUpdated`) only when something actually changed.
- `recentlySavedPosts` safeguard: protects newly saved items for 90 seconds so background sync doesn't purge items while Eagle is still downloading them.
- `withStorageLock()` serializes read-modify-write of the storage lists (concurrent saves no longer drop entries).

#### 5. Replace in Eagle
- Triggered from the comparison card: a normal thumbnail save with `replaceEagleId`.
- Before saving, `mergeReplacedItemMetadata()` reads the old item (`/api/item/info`) and carries over manual tags (deduplicated, single-value `rating:`/`parent:` taken from the new copy when present), first folder, star rating and annotation.
- The old item is moved to trash only after the new one was saved successfully.

## Data Flow

### Post Page Save
```
main.js init() → parser.parse() → panel.updateData() → user clicks Save
  → chrome.runtime.sendMessage({action:'enqueueDownload'})
  → queue.enqueue() → parallel download (or direct URL delegation)
  → sequential FIFO save → Eagle API (POST /api/item/addFromURL)
```

### Thumbnail Save (Two-Phase Enqueue)
```
Thumbnail Click → sendMessage({action:'saveFromMainPage', directPostUrl})
  → handleHiddenTabParse() → queue.enqueue(state:'pending_parse') → return position
  → _parseHiddenTabInBackground() → chrome.tabs.create({url: directPostUrl})
  → waitForCorrectUrl() → parseForMainPageSave()
  → queue.updateParsedData() → stream or delegate → FIFO save → close tab
```

### Collected Check (Main Pages)
```
scanAndAddButtons() → fingerprint locally (readable img) or in page (hashThumbsInPage)
  → sendMessage({action:'checkCollectedBatch', items})
  → exact postKey match │ else getThumbFingerprintBg() (cached) → findBestPHashMatch()
  → detailsMap {type, similarity, distance, queryPHash, queryBlocks, eagleItem}
  → badges; hover → comparison card + getEagleItemInfo (tags, parent)
```

## pHash Collector (`pHash_collector.py`)

Builds `downloaded-db.json` from an Eagle library (`python pHash_collector.py [path] [--full]`).

1. **Metadata**: one `/api/item/list` request when Eagle has this exact library open (~1 s); otherwise reads every `metadata.json` (16 threads).
2. **Incremental**: pHash and block levels are reused from the previous database when the item's `size` and `ext` are unchanged; items without block levels are recomputed once. `--full` recomputes everything.
3. **Fingerprints**: from Eagle's `*_thumbnail.*` (fallback: original file), 16 threads — thumbnail reads are small random I/O that benefits from parallelism even on HDD.
4. Ctrl+C keeps finished results; the database is written atomically (`.tmp` + replace), so the next run continues.

### Database format
```json
{
  "updatedAt": "ISO-8601",
  "posts": ["yandere:1269008", "danbooru:12453338", "..."],
  "items": [{ "id": "EAGLE_ID", "pHash": "64 hex", "blocks": "base64 (256 levels)",
              "w": 2000, "h": 3000, "size": 2448496, "ext": "jpg",
              "name": "post_1269008", "postKey": "yandere:1269008" }]
}
```

## Eagle API Integration

Eagle runs locally on `http://localhost:41595`.

| Endpoint | Method | Payload / Params | Purpose |
|----------|--------|------------------|---------|
| `/api/item/list` | GET | `?limit=10000000` | Connection check & authoritative database sync (full list, ~35 MB for 25k items) |
| `/api/item/info` | GET | `?id=` | Comparison card tags/parent; metadata carried over on Replace |
| `/api/library/info` | GET | — | Library path for the sync safety guard and the collector |
| `/api/item/addFromURL` | POST | `{ url, name, website, tags, annotation, folderId, star, headers }` | Direct URL save or base64 data URI save |
| `/api/item/addFromPath` | POST | `{ path, name, website, tags, annotation, folderId }` | Local file import |
| `/api/item/moveToTrash` | POST | `{ itemIds: [...] }` | Trash the old item after a successful Replace |
